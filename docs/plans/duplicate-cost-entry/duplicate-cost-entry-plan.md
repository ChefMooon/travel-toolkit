# Specification & Overview

### 1. Scope & Objective
- **Goal:** Add a duplicate icon button between Edit and Delete in each cost row. Activating it creates a new cost entry directly below that row in ledger order and remains usable in the mobile card layout.
- **In-Scope:**
  - Add a row-level duplicate action with an accessible, cost-specific name and tooltip.
  - Copy the source cost's name, currency, value, markup override, split type, assigned couples, and optional type. Generate a distinct ID and sort order; copy the assigned-couple ID array independently.
  - Insert the duplicate immediately after its source in the order displayed by `CostLedger`, preserving the relative order of all other entries and marking the trip dirty.
  - Respect the existing 1,000-entry limit and its warning behavior.
  - Fit the third action into the desktop actions column and mobile row-card layout.
  - Add focused store and component coverage.
- **Out-of-Scope:**
  - No schema or saved-trip format changes.
  - No changes to add, edit, delete, bulk selection, or drag-reorder behavior.
  - No name suffix, duplicate confirmation dialog, bulk-duplicate feature, or automatic edit of the newly created entry.

### 2. Technical Constraints & Architecture
- `CostLedger` sorts costs by `sortOrder`; `addCost` assigns the last position and `reorderCosts` reindexes an explicit ID order. A duplicate must therefore use an insertion operation that knows the source ID rather than append via `addCost`.
- `CostEntry` contains the fields to copy, with `type` optional. Existing IDs are generated by the trip store, and successful cost changes set `isDirty`.
- The store already enforces `MAX_COST_ENTRIES` and emits a warning toast when the limit is reached. Duplication must not bypass this guard.
- `CostRow` currently receives edit/delete callbacks and renders those actions in `.row-acts`. `CostLedger` owns row wiring and supplies the sorted entries.
- `src/index.css` sets 27px `.ibtn` controls with a 3px `.row-acts` gap, a 58px desktop actions-column width, and places the actions cell at the right of the first row in the mobile card layout. The desktop column and corresponding header declaration must accommodate three controls; the mobile grid must remain free of clipping and horizontal overflow.
- Existing focused coverage is in `src/store/tripStore.test.ts`, `src/components/CostRow/CostRow.test.tsx`, and `src/components/CostLedger/CostLedger.test.tsx`. `src/responsive.test.tsx` mocks `CostLedger`, so it cannot verify the ledger's row-action layout. The `test` script runs Vitest; `npm run build` includes TypeScript project compilation.
- **Assumptions:** “Duplicate” means an exact copy of the visible cost data, including the same name, with only identity and ordering regenerated. The row action targets its own cost, independent of the bulk-selection checkbox, and does not change bulk selection. Keep the existing action-button size unless viewport checks require a mobile-only adjustment; do not make the controls smaller.
- **Open Decisions:** None.
- **Risks:** A UI-only append followed by a reorder could place the duplicate incorrectly or depend on a newly generated ID that `addCost` does not return. Store-owned insertion avoids that split operation. The added control also requires updating the desktop width in both CSS and the table header declaration.
